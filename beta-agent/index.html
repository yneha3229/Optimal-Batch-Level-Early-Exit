    How it works

    The problem. A server broadcasts to receivers; receiver i wants message xi and already has some others (the arrows). β is the fewest transmissions that let everyone decode. Computing it exactly is out of reach in general, so we trap it between two checkable numbers.
    Lower bound (MAIS). If a set of receivers has no directed cycle among them, order them so each knows only messages of later ones; then no scheme can serve them in fewer than one transmission each. The largest such set gives L.
    Upper bound (clique cover). A group in which everyone has everyone else's message needs one transmission: the XOR of the group's messages. Covering all receivers with U such groups gives a valid scheme with U transmissions.
    The agent. It reads the graph, splits it into strongly connected components (both bounds add up over them), calls greedy, local-search and exact tools in a cost-aware order, reads each verified result, and stops when L = U (β found) or both bounds are proven optimal. It runs offline, with no language model.
